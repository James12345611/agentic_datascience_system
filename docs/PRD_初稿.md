# 数据科学智能平台 PRD 初稿

## 1. 文档信息

- 文档名称：数据科学智能平台 PRD 初稿
- 版本：V0.2
- 状态：持续迭代
- 目的：明确平台当前定位、核心能力、阶段范围、用户流程与产品化方向

## 2. 产品背景

应用统计、数据分析和建模工作，往往分散在多个工具中完成，例如 Excel、Python 脚本、Notebook、统计软件、BI 工具等。对于研究生、独立开发者或小团队，这种方式存在明显问题：

- 数据接入、预处理、统计检验、建模、可视化彼此割裂
- 大量环节依赖人工经验，缺少标准流程
- 字段含义、处理参数、模型配置和结果解释难以沉淀
- 分析过程难复现，结果难追踪

因此，本项目要构建一个面向中文数据分析场景的智能工作台，把“数据进入系统到结果输出”的主链路统一起来，并由 agent 提供辅助理解、建议和解释能力。

## 3. 产品定位

本产品定位为：

`面向应用统计与数据科学任务的智能分析工作台`

它不是让 agent 直接取代统计与建模引擎，而是采用以下职责划分：

- agent：理解任务、发现风险、推荐方案、解释结果
- 规则与算法模块：实际执行预处理、统计检验、诊断与建模
- 任务与存储系统：记录过程、参数、日志和结果版本

## 4. 目标用户

### 核心用户

- 应用统计相关研究生
- 数据分析初学者
- 研究型用户
- 希望独立开发数据产品的个人开发者

### 用户特征

- 具备一定统计学基础
- 熟悉 Python 或愿意以 Python 为主线开发
- 需要从原始表格数据快速走到分析与建模阶段
- 希望系统尽可能提供中文化、流程化和可解释支持

## 5. 产品目标

### 长期目标

构建完整的数据科学智能平台，覆盖：

- 数据接入
- 数据质量检查
- 数据预处理
- EDA
- 统计检验
- 特征工程
- 经典统计建模
- 机器学习建模
- 深度学习建模
- 时序分析
- 结果解释
- 指标体系输出
- 可视化看板与报告生成

### 当前阶段目标

当前优先建立一条稳定的主链路：

`数据上传 -> 字段识别/人工纠偏 -> 预处理 -> EDA/诊断 -> 建模 -> 任务记录与可视化查看`

## 7. 核心使用场景

### 场景 1：论文或课题的数据准备

用户上传数据集，系统自动识别字段类型，提示缺失值、异常值、比例字段、时间字段、疑似标识字段等，再由用户修订字段字典并执行预处理，为后续统计检验和建模做好准备。

### 场景 2：快速判断数据是否适合建模

用户希望知道当前数据是否能进入建模。系统应给出数据质量摘要、字段风险提示、时间字段范围、类别失衡、异常值比例与推荐处理方式。

### 场景 3：在一个工作台中完成分析闭环

用户不希望在多个工具之间切换，希望在同一平台中完成：

- 数据上传
- 预处理
- 统计检验
- 建模
- 日志查看
- 结果回看

## 8. 用户流程

### 当前推荐流程

1. 用户上传 CSV 或 Excel
2. 系统自动生成字段识别结果和数据质量摘要
3. 用户在人机协同界面修订字段字典
4. 用户执行预处理任务
5. 系统保存预处理结果与任务日志
6. 用户查看 EDA、统计诊断和模型结果
7. 用户通过任务中心回看任务状态与历史记录

## 9. Agent 设计原则

平台里的 agent 当前应承担“辅助决策与解释”的职责，而不是直接执行不可见的数据修改。

### 推荐 agent 角色

#### 1. Orchestrator Agent

负责识别当前阶段属于预处理、统计诊断还是建模，并调度相应模块。

#### 2. Data Profiling Agent

负责总结数据结构、识别风险字段、解释字段类型和质量问题。

#### 3. Preprocess Planner Agent

根据字段字典、质量结果和任务目标，推荐预处理策略。

#### 4. Stats Agent

负责推荐统计检验方法、提示前提条件并解释结论。

#### 5. Model Agent

根据任务类型和目标变量推荐建模方法，并解释模型输出。

#### 6. Report Agent

负责将分析过程整理成摘要、报告或结论文本。

### 当前实际启用建议

在当前版本里，优先启用：

- Data Profiling Agent
- Preprocess Planner Agent

原因是当前主线仍然是把数据预处理和分析链路做稳，而不是提前引入复杂多 agent 协商机制。

## 10. 核心功能需求

### 数据接入

- 上传 CSV / Excel
- 查看数据集目录
- 查看原始数据预览

### 字段理解

- 自动识别字段类型
- 支持人工修订数据类型
- 支持维护语义类型、单位、范围、备注
- 支持保存修订历史

### 数据预处理

- 删除无效列
- 缺失值填充
- 异常值处理
- 编码
- 缩放
- 时间字段拆解
- 结果落库

### 分析与建模

- EDA
- 统计检验
- 统计诊断
- 经典统计建模
- 机器学习建模

### 任务与监控

- 任务列表
- 单任务状态
- 任务日志
- 运行监控

## 11. 非功能需求

### 中文化

- 面向中国用户，界面和说明应尽量全中文

### 可追溯

- 每次任务都应记录参数、状态、日志和结果摘要

### 可复现

- 同一配置应可以重复执行

### 可扩展

- 预处理、诊断、建模模块应可继续扩充

## 12. 技术方案

### 当前方案

- 后端：Python + FastAPI
- 原型前端：Streamlit
- 正式前端方向：React + TypeScript
- 数据处理：Pandas、scikit-learn、statsmodels、SciPy
- 数据库存储：SQLite

### 后续升级方向

- 任务异步化：Celery / RQ + Redis
- 业务数据库：PostgreSQL
- 文件与产物：MinIO / 对象存储
- 部署：Docker + Nginx

## 13. 当前与文档初稿相比的进展

项目已经不再停留在“设想”阶段，而是完成了以下关键跨越：

- 从本地函数到 FastAPI 接口
- 从单一 Streamlit 到 React 工作台联调
- 从内存流程到 SQLite 持久化
- 从一次性预处理到任务中心与日志结构

这意味着后续 PRD 的重点不再是“要不要做这些模块”，而是“如何把这些模块做深、做稳、做成正式产品”。

## 14. 当前成功标准

当前阶段可以用以下标准判断是否推进有效：

- 用户可在 React 工作台完成真实接口联调
- 数据上传、预处理、建模链路可跑通
- 字段字典修订可以持久化
- 任务与日志可以回看
- 文档、代码和接口状态保持一致
