# 数据科学智能平台 PRD 初稿

## 1. 文档信息

- 文档名称：数据科学智能平台 PRD 初稿
- 版本：v0.1
- 状态：初稿
- 编写目的：用于明确平台第一阶段的产品定位、核心能力、用户流程、系统边界与 V1 建设重点

## 2. 产品背景

应用统计、数据分析和机器学习相关工作通常分散在多个工具中完成，例如 Excel、Python 脚本、Jupyter Notebook、统计软件、BI 工具等。对于个人研究者或小型团队来说，这种方式存在以下问题：

- 数据分析流程割裂，数据预处理、统计检验、建模、可视化和报告输出缺乏统一链路
- 大量分析步骤依赖人工经验，难以沉淀标准流程
- 结果复现困难，参数、数据版本、处理步骤和模型配置难以系统追踪
- 非工程背景用户难以快速完成规范的数据分析流程

因此，需要构建一个面向数据科学全流程的智能平台，将数据处理、统计分析、建模实验和结果表达整合到统一工作台中，并通过 Agent 提供辅助理解、方法推荐与结果解释能力。

## 3. 产品定位

本产品定位为：

**一个面向应用统计与数据科学任务的智能分析工作台。**

平台并不让 Agent 直接替代数据处理与建模引擎，而是采用以下原则：

- Agent 负责理解需求、生成方案、推荐方法、解释结果
- 规则引擎与算法模块负责执行数据处理、检验和建模任务
- 所有关键过程沉淀为可追踪的实验记录与分析产物

## 4. 目标用户

### 4.1 核心用户

- 应用统计专业学生
- 数据分析初学者
- 研究型用户
- 需要快速搭建分析流程的独立开发者

### 4.2 典型用户特征

- 具备一定统计学和 Python 基础
- 需要同时处理表格数据和时间序列数据
- 希望从数据导入到结论输出形成完整闭环
- 希望平台兼顾“工程可执行性”和“统计分析严谨性”

## 5. 产品目标

### 5.1 长期目标

构建一个覆盖以下环节的数据科学智能平台：

- 数据接入
- 数据质量检查
- 数据预处理
- 探索性分析
- 统计检验
- 特征工程
- 统计建模
- 机器学习建模
- 深度学习建模
- 时序分析
- 结果解释
- 指标体系输出
- 可视化看板与报告生成

### 5.2 第一阶段目标

第一阶段优先聚焦在“数据预处理工程能力”的建设，形成后续统计检验和建模的基础底座。

第一阶段需要达成以下目标：

- 支持用户上传和读取常见结构化数据
- 自动生成数据画像和基础质量报告
- 支持常见的数据清洗和预处理操作
- 保留预处理配置与日志，保证可复现
- 提供可视化原型界面，便于在测试环境验证流程效果

## 6. 产品范围

### 6.1 全局功能范围

平台长期将包含以下能力模块：

1. 项目管理
2. 数据接入

4. 数据预处理
5. 探索性分析
6. 统计检验

9. 模型评估与解释
10. 报告与看板
11. 实验与版本管理
12. Agent 协同与分析辅助

### 6.2 V1 范围

V1 只建设以下内容：

1. 数据上传与读取
2. 字段类型识别
3. 数据质量检查
4. 数据预处理流程编排
5. 预处理结果导出

### 6.3 V1 暂不包含

## 7. 核心使用场景

### 场景 1：研究生完成论文前的数据处理准备

用户上传问卷、实验或业务数据，平台自动识别字段类型并输出质量报告，用户根据建议完成缺失值处理、异常值处理、编码和标准化，为后续统计检验和建模做准备。

### 场景 2：用户快速判断数据是否适合建模

平台对数据集进行基础画像，提示缺失情况、类别失衡、异常值比例、时间字段情况、疑似 ID 列和高基数字段，帮助用户判断数据是否适合进入建模阶段。

### 场景 3：用户在测试环境验证预处理链路

用户通过 Web 原型界面上传数据集、勾选预处理策略、查看前后对比结果和处理日志，验证设计方案是否合理。

## 8. 用户流程

### 8.1 全链路目标流程

1. 创建项目
2. 上传数据
3. 自动数据画像
4. 查看质量报告
5. 选择或接受预处理建议
6. 执行预处理流程
7. 查看处理前后差异
8. 导出清洗后数据和处理配置
9. 进入后续统计检验或建模模块

### 8.2 V1 重点流程

1. 用户进入测试界面
2. 上传 CSV 或 Excel 数据
3. 系统自动展示字段概览与质量检查结果
4. 用户选择预处理策略
5. 系统执行预处理 Pipeline
6. 系统展示结果摘要、日志和导出文件

## 9. Agent 设计原则

平台中的 Agent 不应直接替代底层算法模块，而应承担“辅助决策与解释”的职责。

### 9.1 Agent 总体职责

- 理解用户分析目标
- 识别当前数据问题
- 推荐合理方法
- 解释执行结果
- 帮助串联分析链路

### 9.2 推荐的 Agent 角色

#### 1. Orchestrator Agent

职责：

- 理解用户任务
- 判断当前处于数据处理、统计检验还是建模阶段
- 调用相应模块与子 Agent

#### 2. Data Profiling Agent

职责：

- 解读字段含义和数据结构
- 总结数据质量问题
- 输出数据画像结论

#### 3. Preprocess Planner Agent

职责：

- 根据数据特征推荐清洗和预处理策略
- 提醒潜在数据泄漏风险
- 解释不同处理方式的适用场景

#### 4. Stats Agent

职责：

- 推荐统计检验方法
- 审查检验前提
- 解释统计结论

#### 5. Model Agent

职责：

- 根据任务类型推荐建模方案
- 管理统计模型、机器学习模型和时序模型的路由

#### 6. Report Agent

职责：

- 整理分析过程
- 输出可读报告和结论摘要

### 9.3 V1 实际启用的 Agent

V1 建议只启用以下两个：

- Data Profiling Agent
- Preprocess Planner Agent

原因：

- V1 的目标是验证“数据预处理链路”，无需过早引入复杂多 Agent 机制
- 预处理阶段最适合通过 Agent 提供建议和解释，但具体执行仍应由确定性 Pipeline 完成

## 10. 功能需求

### 10.1 项目管理

V1 可简化为本地项目目录结构，不要求完整项目管理系统。

基础要求：

- 支持创建项目名称
- 按项目保存数据文件、处理结果和日志

### 10.2 数据接入

功能要求：

- 支持上传 CSV、XLSX 文件
- 支持读取首行字段名
- 支持选择工作表
- 支持预览数据前若干行
- 支持基础编码兼容处理

### 10.3 字段识别

功能要求：

- 自动判断数值型字段
- 自动判断分类型字段
- 自动判断时间型字段
- 自动识别可能的 ID 列
- 自动识别高基数字段

### 10.4 数据质量检查

功能要求：

- 缺失值统计
- 重复值统计
- 字段唯一值统计
- 数值分布摘要
- 异常值检测
- 类型异常提示
- 类别分布摘要
- 时间字段完整性检查

### 10.5 数据预处理

功能要求：

- 删除无效列
- 类型转换
- 缺失值填补
- 重复值处理
- 异常值处理
- 编码处理
- 标准化/归一化
- 数据集切分

### 10.6 结果输出

功能要求：

- 导出清洗后数据
- 导出质量报告
- 导出预处理配置
- 导出处理日志

### 10.7 原型界面

功能要求：

- 文件上传页
- 数据预览区
- 质量检查区
- 预处理策略设置区
- 执行结果展示区
- 导出按钮

## 11. 非功能需求

### 11.1 可复现性

- 所有预处理步骤必须记录参数
- 同一配置应可重复执行并得到一致结果

### 11.2 可扩展性

- 预处理模块应支持后续扩展统计检验和建模模块
- 各环节应模块化封装，避免与界面强耦合

### 11.3 易用性

- 面向统计专业学生，界面和术语应清晰
- 尽可能提供默认建议，降低初期使用门槛

### 11.4 性能

- V1 优先支持中小规模结构化数据
- 暂不强求超大数据分布式处理

## 12. 推荐技术方案

### 12.1 V1 技术路线

- 编程语言：Python
- 数据处理：pandas
- 机器学习预处理：scikit-learn
- 数据校验：pandera 或 pydantic
- 可视化：plotly
- 原型前端：Streamlit

### 12.2 后续可升级方向

- 接口层：FastAPI
- 正式前端：React + TypeScript
- 任务调度：Celery 或异步任务队列
- 存储：PostgreSQL + 对象存储
- 实验管理：MLflow 或自定义实验管理模块

## 13. 核心数据对象

建议先定义以下核心对象：

- Project：项目
- Dataset：原始数据集
- ProfileReport：数据画像报告
- PreprocessConfig：预处理配置
- PreprocessRun：预处理执行记录
- CleanDataset：清洗后数据集
- Artifact：导出产物

## 14. 成功指标

V1 可先用以下指标衡量是否有效：

- 用户可成功上传并读取常见表格数据
- 系统可自动输出字段类型识别和质量检查结果
- 用户可完成至少一条完整预处理流程
- 系统可导出处理后数据与配置文件
- 用户可以根据报告理解主要数据问题

## 15. 风险与约束

### 15.1 风险

- 数据类型识别可能存在误判，需要人工覆写机制
- 自动预处理建议不一定适合所有研究场景
- 不同数据源编码、日期格式和脏数据情况复杂
- 如果前期过度依赖 Agent，可能导致流程不可控

### 15.2 应对策略

- 先支持人工调整字段类型
- 先实现常见规则，避免过度自动化
- 执行层坚持规则化和可配置化
- Agent 仅负责建议与解释，不直接主导计算逻辑
