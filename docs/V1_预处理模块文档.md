# V1 预处理模块文档

## 1. 文档目标

本文档用于定义数据科学智能平台 V1 中“数据预处理模块”的设计范围、能力边界、核心流程、模块划分、输入输出、技术实现建议与开发优先级，作为后续编码实现的依据。

## 2. 模块定位

数据预处理模块是整个平台的基础底座，负责将原始结构化数据转换为可用于统计检验、建模与可视化分析的标准化数据资产。

该模块的职责不是完成所有分析任务，而是解决以下问题：

- 数据能否被正确读入
- 数据字段是否被正确识别
- 数据是否存在明显质量问题
- 数据是否需要清洗与转换
- 数据是否具备后续分析所需的基本条件

## 3. V1 范围

### 3.1 包含内容

- CSV / Excel 数据读取
- 数据预览
- 字段类型识别
- 数据质量检查
- 基础清洗
- 基础特征变换
- 数据切分
- 处理结果导出
- 预处理日志记录

### 3.2 不包含内容

- 特征自动生成
- 复杂特征筛选
- 深度数据修复
- 图像、文本、音频数据预处理
- 大规模分布式数据处理
- 在线实时流式数据处理

## 4. 使用目标

V1 需要支持用户完成如下最小闭环：

1. 上传原始数据文件
2. 查看字段和样本预览
3. 获取自动质量检查结果
4. 选择预处理策略
5. 执行处理流程
6. 查看处理前后摘要
7. 导出处理后数据和配置文件

## 5. 目标数据类型

V1 优先支持结构化表格数据。

支持类型：

- 数值型变量
- 分类型变量
- 布尔型变量
- 时间型变量
- 简单文本型变量

暂不重点支持：

- 长文本语料
- 图像数据
- 图结构数据
- 多模态数据

## 6. 核心功能设计

## 6.1 数据读取

### 功能说明

负责读取用户上传的数据文件并转换为内部 DataFrame 对象。

### 输入

- `csv`
- `xlsx`

### 输出

- 原始 DataFrame
- 文件元信息
- 读取日志

### 处理要求

- 支持首行作为字段名
- 支持选择 Excel 工作表
- 支持编码兼容
- 支持读取失败提示
- 支持前若干行预览

## 6.2 字段类型识别

### 功能说明

自动识别各列的数据类型，并给出可人工修正的建议结果。

### 目标类型

- numerical
- categorical
- datetime
- boolean
- text
- id_like

### 识别规则建议

- 可直接转为数值的列优先识别为 numerical
- 取值种类较少且非连续数值的列可识别为 categorical
- 可稳定解析为日期格式的列识别为 datetime
- 唯一值接近样本量且无明显分析意义的列标记为 id_like
- 超高基数的字符串列提示谨慎编码

### 输出

- 字段类型映射表
- 类型识别置信提示
- 人工修正入口

## 6.3 数据质量检查

### 功能说明

对原始数据进行规则化检查，形成结构化质量报告。

### 检查项

#### 表级检查

- 样本数
- 字段数
- 重复记录数
- 完全空行数

#### 字段级检查

- 缺失值数量与比例
- 唯一值数量与比例
- 数据类型异常
- 常见非法值统计
- 极端值分布
- 类别不平衡提示

#### 数值字段检查

- 均值
- 标准差
- 最小值
- 最大值
- 分位数
- IQR 异常值数量

#### 分类型字段检查

- 类别数量
- Top N 频次分布
- 稀有类别提示

#### 时间字段检查

- 最早时间
- 最晚时间
- 时间缺失
- 时间解析失败
- 时间重复与时间间隔异常提示

### 输出

- 质量报告对象
- 可视化摘要数据
- 风险提示列表

## 6.4 基础清洗

### 功能说明

执行数据清洗，消除明显错误和基础脏数据。

### 支持能力

- 删除重复行
- 删除全空列
- 删除高缺失列
- 删除单一值列
- 类型转换
- 缺失值填补
- 异常值截断或替换

### 缺失值策略

数值型字段：

- 均值填补
- 中位数填补
- 固定值填补

分类型字段：

- 众数填补
- 固定类别填补

时间字段：

- 保留为空
- 固定日期填补

### 异常值策略

- IQR 截断
- 分位数截断
- 删除异常样本
- 保留并仅提示

## 6.5 基础变换

### 功能说明

将清洗后的字段转换为适合后续分析与建模的格式。

### 支持能力

- One-Hot 编码
- Label Encoding
- 标准化
- Min-Max 归一化
- 日期字段拆解

### 日期拆解建议

- year
- month
- day
- weekday
- quarter

### 注意事项

- 保留原字段与派生字段的映射关系
- 编码策略必须记录
- 标准化参数必须可复用

## 6.6 数据切分

### 功能说明

为后续建模保留训练集与测试集划分能力。

### 支持能力

- 随机切分
- 按比例切分
- 固定随机种子
- 分类任务分层抽样
- 时间序列按时间切分

### 输出

- train dataset
- valid dataset
- test dataset
- split metadata

## 6.7 结果导出

### 导出产物

- 清洗后数据文件
- 字段类型配置文件
- 预处理参数配置文件
- 质量检查报告文件
- 执行日志文件

### 推荐格式

- 数据文件：`csv`
- 配置文件：`json`
- 报告文件：`json` 或 `html`
- 日志文件：`log` 或 `json`

## 7. Agent 在预处理模块中的作用

V1 中 Agent 不直接执行数据修改，而是提供辅助建议。

## 7.1 Data Profiling Agent

输入：

- 数据概览
- 字段类型结果
- 质量检查结果

输出：

- 数据结构总结
- 主要质量问题说明
- 风险字段提示

## 7.2 Preprocess Planner Agent

输入：

- 字段信息
- 质量报告
- 用户目标任务描述

输出：

- 推荐预处理策略
- 建议删除字段
- 编码建议
- 缺失值处理建议
- 潜在数据泄漏提示

## 7.3 设计原则

- Agent 只生成建议，不直接改动数据
- 最终执行配置必须可见、可编辑、可复现
- 所有建议都应能落到结构化参数上

## 8. 模块架构建议

建议采用“界面层 + 服务层 + 核心处理层 + 存储层”的结构。

### 8.1 目录建议

```text
statistic_platform/
├─ docs/
├─ app/
│  ├─ ui/
│  ├─ services/
│  ├─ core/
│  ├─ schemas/
│  ├─ agents/
│  └─ utils/
├─ data/
│  ├─ raw/
│  ├─ processed/
│  └─ artifacts/
├─ tests/
└─ requirements.txt
```

### 8.2 分层说明

#### `ui/`

负责 Streamlit 页面、文件上传、参数选择和结果展示。

#### `services/`

负责流程编排，将界面请求转给底层模块。

#### `core/`

负责真正的数据处理逻辑。

建议继续拆分为：

- `reader.py`
- `type_infer.py`
- `quality.py`
- `cleaner.py`
- `transformer.py`
- `splitter.py`
- `exporter.py`

#### `schemas/`

定义配置对象、报告对象、字段类型对象等结构。

#### `agents/`

封装数据画像和预处理建议逻辑。

## 10. 预处理执行流程

建议的标准执行顺序如下：

1. 读取数据
2. 生成字段类型初判
3. 生成质量报告
4. 接收用户确认或修正配置
5. 执行基础清洗
6. 执行编码与缩放
7. 执行数据切分
8. 生成产物并导出

这样设计的原因是：

- 先做画像和检查，避免盲目清洗
- 用户可以在执行前修正类型判断
- 清洗与变换步骤具备稳定顺序，便于复现

## 11. 前端原型建议

由于当前开发者主要掌握 Python，V1 建议使用 `Streamlit`。

### 原因

- 开发门槛低
- 与 pandas/plotly 集成方便
- 适合快速构建测试环境原型
- 有利于先验证流程，再决定是否升级为前后端分离架构

### 页面建议

#### 页面 1：数据上传

- 上传文件
- 选择工作表
- 查看样本预览

#### 页面 2：字段与质量报告

- 字段类型表
- 缺失值统计
- 重复值统计
- 数值摘要
- 风险提示

#### 页面 3：预处理配置

- 删除列选择
- 缺失值策略选择
- 编码方式选择
- 缩放方式选择
- 切分配置

#### 页面 4：执行结果

- 处理前后维度对比
- 处理日志
- 导出文件下载

## 13. 配置化设计建议

V1 就应该把预处理做成“配置驱动”而不是“写死流程”。

示例：

```json
{
  "drop_columns": ["user_id"],
  "type_overrides": {
    "date": "datetime",
    "label": "categorical"
  },
  "missing_strategies": {
    "age": "median",
    "gender": "mode"
  },
  "encoding_strategies": {
    "gender": "onehot",
    "city": "onehot"
  },
  "scaling_strategies": {
    "income": "standard"
  },
  "split_config": {
    "method": "random",
    "test_size": 0.2,
    "random_state": 42
  }
}
```

## 14. 测试建议

V1 至少应覆盖以下测试：

### 单元测试

- CSV 读取是否正确
- Excel 读取是否正确
- 类型识别规则是否按预期工作
- 缺失值填补是否正确
- 编码结果是否符合预期

### 集成测试

- 一份样例数据是否可从上传走到导出
- 预处理前后样本量和字段数变化是否可解释
- 配置重跑结果是否一致

### 样例数据建议

- 普通结构化表格数据
- 含缺失值数据
- 含异常值数据
- 含时间字段数据
- 含分类字段数据

- 导出结果

### P1

- Agent 建议摘要

### P2

- 预处理模板保存
- 批量数据集处理
- 与后续建模模块联动

## 16. 开发顺序建议

建议按以下顺序开发：

1. 先写 `reader`
2. 再写 `type_infer`
3. 再写 `quality`
4. 再写 `cleaner`
5. 再写 `transformer`
6. 再写 `splitter`
7. 最后接 `Streamlit UI`

理由：

- 先保证底层处理能力稳定
- 再接前端，避免界面先行导致逻辑频繁返工

## 17. V1 完成标准

满足以下条件时，可认为预处理模块 V1 完成：

- 用户可以上传 CSV 或 Excel 文件
- 系统可自动输出字段识别和质量报告
- 用户可配置至少一套常见预处理方案
- 系统可执行并导出结果
- 处理日志与配置可追踪
- 界面可在测试环境稳定运行
